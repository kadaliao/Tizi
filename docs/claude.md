# Claude 线路保护

`claude.ai`、`claude.com`、`anthropic.com`、`claudeusercontent.com` 固定走「Claude」线路。这条线路没有直连选项，自定义规则也改不了，这些域名的 UDP 流量直接拦截；一个代理节点都没有时 Claude 直接打不开，不会直连。

## 住宅节点

可以给 Claude 单独配一个住宅节点，让 Claude 看到固定的住宅 IP。

- 桌面版在「配置」页的「Claude」一节按项填写协议、主机、端口、用户名和密码。服务商给的整段地址可以直接粘贴到「主机」，会自动拆开（`socks5://用户名:密码@主机:端口`、`主机:端口:用户名:密码` 等常见写法都认识）。
- 终端版在「Claude 住宅节点」填完整地址。
- ss、trojan、vless 等其他协议点「编辑 claude-proxy.yaml…」，按 Mihomo 节点格式写。

连接方式有两种：

- **经前置代理链式连接**（默认）：本机 → 「前置代理」（订阅或节点文件里的节点）→ 住宅节点。从国内访问住宅节点更稳定，Claude 看到的是住宅 IP。可以在「策略」页给「前置代理」选一个固定的节点。
- **本机直接连接**：本机 → 住宅节点。国内直连明文的 HTTP / SOCKS5 节点容易被干扰，建议用加密协议。没有任何代理节点、或节点地址是本机（例如 SSH 端口转发出来的 `127.0.0.1`）时，总是直接连接。

住宅节点连不上时，Claude 打不开并弹窗，不会自动换线路，避免出口 IP 来回切换。急用时可以在弹窗或策略页把「Claude」临时切到其他代理节点，重新连接或重载 Mihomo 后会自动切回住宅节点。

## 访问监测

配置了住宅节点时自动开启；没配置时可以在「配置」页打开「Claude 访问监测」。检测请求的是 `https://claude.ai/cdn-cgi/trace`，由 Cloudflare 边缘直接返回出口 IP 和地区，不带账号信息，也不到达 Anthropic 的服务器。

平时每 30 秒检测一次；Mihomo 退出，或日志里出现 Claude 直连、连接失败时立即检测。出现下面任一情况，几秒内弹出置顶的提醒，并给出对应的处理按钮：

- 连接意外断开，这时访问 Claude 会直连
- 经住宅节点（或代理节点）连不上 Claude
- Claude 的连接走了直连，或配了住宅节点却没经过它
- 出口 IP 在中国大陆、香港或澳门

其他细节：

- 一次检测失败后 3 秒复查，仍失败才弹窗；同一个问题只弹一次，恢复后窗口变成绿色的「已恢复」。
- 桌面版没开时（用终端版，或「保持运行退出」后），由后台进程用 macOS 系统弹窗提醒。
- 整机断网时只提示「网络已断开」；睡眠唤醒后 30 秒内不弹「连不上」。关闭 TUN、或改了住宅节点还没重载时，状态页显示橙色提示，不弹窗。
- 主动断开或选「停止并退出」后，访问 Claude 会直连，不会提醒；需要彻底防止直连时打开直连保护。
- Ubuntu 上没有弹窗，用 `tizi claude-check` 检查，有问题时退出码非零。

## 直连保护（macOS）

在「配置」页打开「直连保护」（终端版「Claude 直连保护」，或 `tizi claude-block on`），需要输入一次登录密码。它用系统自带的 pf 防火墙拦截不经隧道、直接发往 Anthropic 网段（`160.79.104.0/21`、`2607:6bc0::/32`）的连接。

- 连接正常时没有影响，Claude 的流量走 TUN 隧道。
- 断开、崩溃或开机后还没连接时，Claude 直接打不开，不会直连。
- 开机时由系统后台任务 `/Library/LaunchDaemons/com.kadaliao.tizi.claude-block.plist` 加载规则，之后每分钟检查一次；规则挂在 `/etc/pf.conf` 已有的 `com.apple/*` 锚点下，不修改 pf.conf。
- 诊断页、`claude-block status` 和访问监测都会自检是否生效；自检不接触 Anthropic 的真实地址。
- 关闭时删除规则和后台任务。`downloads.claude.ai` 不在 Anthropic 网段，不受保护；Ubuntu 暂不支持。
